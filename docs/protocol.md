# Протокол (v1)

Все сообщения — little-endian, первый байт — тип сообщения. Пакет
`internal/protocol` содержит типы и кодек и не зависит ни от игры, ни от сети.

> **Статус кодека.** С итерации 3 кодек **бинарный** (little-endian), как описано
> ниже; временный JSON итерации 1 удалён. Типы и публичные функции (`Append*`,
> `Decode*`) переезд не заметили — менялась только кодировка. Квантование позиций
> и скоростей вынесено в `quantize.go`.

## Требования к кодеку

1. **Никогда не паниковать** на мусорном/обрезанном вводе — только ошибки.
   Гарантируется фаззингом (`FuzzDecode`).
2. **Round-trip без потерь**: `encode → decode` возвращает исходное значение.
   Property-тест на случайных сообщениях.
3. **Zero-alloc encode** при переиспользуемом буфере (цель итерации 3;
   бенчмарк `BenchmarkEncodeSnapshot` должен показывать 0 allocs/op).

## Типы сообщений

| Код    | Имя           | Направление |
|--------|---------------|-------------|
| `0x01` | `MsgInput`    | клиент → сервер |
| `0x02` | `MsgJoin`     | клиент → сервер |
| `0x10` | `MsgSnapshot` | сервер → клиент |
| `0x11` | `MsgJoinAck`  | сервер → клиент |
| `0x12` | `MsgSpawn`    | сервер → клиент (reliable, итер. 5) |
| `0x13` | `MsgDeath`    | сервер → клиент (reliable, итер. 5) |
| `0x14` | `MsgHit`      | сервер → клиент (reliable, итер. 5) |

## Клиент → сервер

### MsgInput (0x01)

Формат на проводе:

```
[1B type][4B seq uint32][1B buttons][2B aim uint16]
```

- **seq** — порядковый номер ввода (клиент шлёт 60 Гц). Используется для
  reconciliation: сервер возвращает `lastProcessedSeq`.
- **buttons** — битовая маска: бит 0..3 = WASD (`Up/Left/Down/Right`), бит 4 = fire.
- **aim** — угол прицеливания, `0..65535` отображается на `0..2π`.

### MsgJoin (0x02)

```
[1B type][1B nameLen][name UTF-8, max 16B]
```

Имя валидируется: не длиннее 16 байт и корректный UTF-8.

## Сервер → клиент

### MsgSnapshot (0x10)

```
[1B type][4B tick][4B lastProcessedSeq][1B count]
  затем count × [2B id][1B kind][2B x][2B y][2B vx][2B vy][1B hp]
```

- **lastProcessedSeq** — **своё для каждого получателя**: номер последнего ввода
  этого клиента, применённого сервером. На нём строится клиентская реконсиляция.
- **координаты квантуются**: карта 4096×4096, шаг 1/16 юнита (`CoordScale`).
- **count** — один байт, поэтому в снапшоте не больше 255 сущностей (`MaxEntities`).

### MsgJoinAck (0x11)

```
[1B type][2B yourID][4B tick]
```

Сообщает клиенту его собственный `id` сущности и текущий тик.

### MsgSpawn / MsgDeath / MsgHit (0x12–0x14)

Reliable-события. Появятся в итерации 5 (стрельба и смерти). В отличие от
снапшотов, их нельзя дропать: сессия, которая не может их принять, помечается на
отключение, а не теряет событие.

## Константы (единый источник — `protocol` + `game`)

| Константа       | Значение | Смысл                                  |
|-----------------|---------:|----------------------------------------|
| `MapSize`       |     4096 | сторона карты в юнитах                  |
| `CoordScale`    |       16 | шаг квантования координат (1/16 юнита)  |
| `MaxNameLen`    |       16 | максимум длины имени, байт             |
| `MaxEntities`   |      255 | максимум сущностей в снапшоте           |

> ⚠️ **Синхронизация с клиентом.** Клиент (`web/game.js`) зеркалит формат и
> игровые константы (скорость, радиус). При изменении протокола или движения
> правьте обе стороны в одном коммите, иначе рассинхрон проявится как «дрейф»
> предсказания, а не как ошибка компиляции.

## Golden- и fuzz-файлы

- `internal/protocol/testdata/*.golden` — эталонные байтовые дампы. Обновляются
  осознанно: `go test ./internal/protocol -update`, затем ревью диффа.
- Корпус фаззера (`testdata/fuzz/`) в git не коммитится (см. `.gitignore`);
  сид-корпус задан прямо в `FuzzDecode`.
